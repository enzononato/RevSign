# RevSign — alterações sobre o Documenso

Base: Documenso `v2.21.1` (`8707e33c`). Repositório: https://github.com/enzononato/RevSign

Este arquivo é o guia para trazer novas versões do upstream (`git fetch upstream --tags && git merge vX.Y.Z`).
Toda edição em arquivo do upstream é marcada com `REVALLE:` no código e listada abaixo.

## Checklist de atualização do upstream

1. `git fetch upstream --tags` e ler o changelog da nova versão.
2. `git merge vX.Y.Z` na branch `revalle` (merge, nunca rebase).
3. Resolver conflitos; conferir cada linha desta tabela (`git grep -n "REVALLE:"`).
4. Revisar migrações novas em `packages/prisma/migrations/` (rodam sozinhas no start).
5. **Tradução e marca** (Fase 2):
   1. Rode `npm run translate:revalle` (extract, overlay, `check-po`, compile). A última linha do `check-po` é o resumo (`N entradas, M sem tradução, K obsoletas no overlay, E erros`); compare com a versão anterior.
   2. Liste o que falta: `node scripts/revalle/i18n/export-missing.mjs packages/lib/translations/pt-BR/web.po` (vazios e traduções com "Documenso"). Traduza cada um no overlay `packages/lib/translations/revalle/pt-BR.po`: mesmos `{placeholders}`, tags `<0>` e ICU; "RevSign" no lugar de "Documenso" (salvo licença/AGPL); "documento" (nunca "envelope"), "recusar", "leitor", "modelo", tom simples com "você". Rode o passo 1 de novo.
   3. Limpe os obsoletos: cada "obsoleto" do `check-po` é uma msgid que o upstream mudou ou apagou. Se o texto só mudou, mova a tradução para a msgid nova (senão a tradução antiga do upstream, ex.: "rejeitado", volta sem aviso); se sumiu, apague a entrada.
   4. O `check-po` tem de terminar com `0 sem tradução, 0 obsoletas no overlay, 0 erros`. Um erro também derruba o build da imagem.
   5. Desfaça os catálogos reescritos: `git checkout -- 'packages/lib/translations/*/web.po'` (o pre-commit recusa commitá-los fora do merge).
   6. Se o upstream mudou imagens (logo, favicon, `packages/assets/images/`, `static/` dos e-mails), rode `sh revalle/brand/generate-assets.sh` e confira o `git diff --stat`. Imagem nova com o verde do Documenso que aparece para quem assina ou envia entra no script.
6. Ensaio local (`revalle/deploy/compose.hml.yml`) + `scripts/revalle/smoke-test.mjs` + `scripts/revalle/verify-signed-pdf.sh`. Com a imagem nova, rode também `branding.test.mjs`, `locale.test.mjs`, `share-hardening.test.mjs` e `scripts/revalle/mobile-check.mjs` (ver `revalle/docs/testes.md`).
7. Tag `vX.Y.Z-revalle.1`, validar em homologação e só depois em produção.
8. Se a nova versão mudar a `@libpdf/core` no `package-lock.json`, o `patches/@libpdf+core+<versão>.patch` precisa ser refeito (o `npm ci` avisa quando não aplica): siga "Atualização da `@libpdf/core`" em `revalle/docs/certificado.md` e rode `scripts/revalle/tests/icp-seal.test.mjs`.
